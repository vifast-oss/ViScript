# VS3-4a — TLS client cho `http.get`/`http.head` (W2, 2026-11-21)

> **Lát**: VS3-4a (VD-271), worktree `vs3/w2-tls`, baseline `9ad29e1`.
> **Trạng thái**: code + test + review dependency xong; **chưa merge**; VS3-4b (HTTP/2,
> keep-alive) **không** làm trong lát này.

## 1. Kết quả

- `http.get(_timeout)` / `http.head(_timeout)` nhận **`https://`**; TLS nằm ở **host CLI**
  (`vis-cli::net`), giao thức HTTP vẫn ở `vis-interp` ⇒ interp ↔ VM **cùng byte** (có ca so).
- Chứng chỉ xác thực theo **root store** (`webpki-roots`, bundle Mozilla); sai gốc/sai tên ⇒
  `Err` dữ liệu có chữ `TLS`, **không panic**.
- Timeout/redirect/HEAD giữ hành vi cũ: một deadline monotonic cho **cả** connect + handshake +
  mọi hop + đọc; redirect GET tối đa 5; HEAD **không** theo redirect; cap body 8 MiB.
- **Không** cho hạ cấp `HTTPS → HTTP` (Q2 (3)); nâng cấp `HTTP → HTTPS` được.
- `http://` **vẫn chỉ loopback** (VD-100/105); `https://` cho host bất kỳ nhưng vẫn qua
  `cap[Net]` như mọi host khác (`NetGuard::connect_tls`).
- Không HTTP/2, không ALPN, không keep-alive/cookie (để VS3-4b).

## 2. Thiết kế

| Thành phần | Thay đổi |
|---|---|
| `vis-interp/src/builtin.rs` | `NetHost::connect_tls(dia_chi, timeout_ms)` — mặc định `Err` rõ; host hỗ trợ thì cài |
| `vis-interp/src/net.rs` | `GiaoThuc::{Http,Https}`, `UrlHttp` (host/cổng/target), cổng mặc định 80/443; `http_get`/`http_head` chọn `connect`/`connect_tls`; `noi_location` giữ scheme + chặn hạ cấp |
| `vis-cli/src/net.rs` | `Kenh::{Tho,Tls}`; `connect_tls` = TCP + handshake trong một hạn; lỗi đọc/ghi TLS có tiền tố riêng |
| `vis-cli/src/net/tls.rs` | `rustls` + `ring`; root store mặc định `webpki-roots`; cấu hình gốc riêng **chỉ test** gọi |
| `vis-cli/src/lib.rs` | Tách `pub mod net` để `tests/vs3_tls.rs` gọi thẳng `Net` + `http_get`/`http_head` |
| `vis-cli/src/quyen.rs` | `NetGuard::connect_tls` kiểm `cap[Net]` trên `host:port` |
| `crates/vis-cli/tests/vs3_tls.rs` | 10 ca với server TLS thật + chứng chỉ tự ký (không Internet) |

**Vì sao TLS ở host, không ở `vis-interp`**: `vis-interp` là crate lõi dùng chung (kể cả wasm);
thêm `rustls`/`ring` vào đó sẽ kéo C/asm vào core và phá ma trận wasm. `NetHost` là ranh giới
socket sẵn có, nên TLS chỉ là một loại "kênh" của host.

**Vì sao có `lib.rs`**: integration test cần dựng server TLS, nạp **gốc test** và gọi đúng
`http_get`; nếu chỉ có binary thì không thể inject gốc mà không thêm cờ/backdoor. `lib` chỉ
chứa `net`; binary `vis` dùng `vis_cli::net::Net`. `Net::moi_voi_goc_tls` là API thư viện,
**không** có cờ dòng lệnh/biến môi trường; root store của binary luôn là `webpki-roots`.

## 3. Feature gate

- `vis-cli` thêm feature **`tls`**, **default-on** cùng `sqlite`:
  `default = ["sqlite", "tls"]`.
- Dependency chỉ khai cho `cfg(not(target_arch = "wasm32"))`; `cargo tree ... --target
  wasm32-unknown-unknown --no-default-features --features tls` **không** có `rustls/ring/webpki`.
- Build core (`--no-default-features`) và wasm32 core: `cargo check` xanh; gọi HTTPS ở cấu hình
  đó trả lỗi dữ liệu:
  `` `https://` cần TLS: feature `tls` của `vis-cli` phải bật và nền không phải wasm32 ``.
- Windows native (MSVC) dùng `ring` như Linux; **cross-check** từ Linux với `--features tls`
  cần `lib.exe` (cùng lớp nợ toolchain C như `sqlite`/#156), nên cấu hình `sqlite` sẵn đỏ ở
  ma trận 18 ô vẫn đỏ; cấu hình **core** (không `tls`) vẫn xanh.
- `./bin/vis-targets` sau thay đổi: **core 18 PASS**, **sqlite 16 PASS + 2 EXPECTED_RED**,
  `FAIL=0` (msvc đỏ ở build `ring`, wasm đỏ ở `libsqlite3-sys`; cả hai là C toolchain).

## 6. Còn lại / chuyển lát sau

- **VS3-4b**: HTTP/2, ALPN, keep-alive, nén, cookie — **chưa** làm; hiện mỗi request một kết nối,
  gửi `Connection: close`.
- **Windows**: chưa chạy runtime TLS trên Windows thật (Tier 2 tới VS3-6); cross-check có TLS cần
  MSVC toolchain (lớp #156). Linux là nền đo chính.
- **Root store**: dùng bundle Mozilla cố định, **không** đọc kho hệ điều hành và **không** có
  proxy/`SSL_CERT_FILE`. Nếu VS3-5 cần cert nội bộ/proxy, phải mở lát riêng + review
  `rustls-native-certs`.
- **IPv6 + `cap[Net]`**: `quyen::kiem_net` tách host bằng `rsplit_once(':')` (cũ), nên cap cho
  IPv6 dạng `[::1]` có thể không khớp `::1`; TLS IPv6 vẫn hoạt động khi không bật cap. Nợ nhỏ,
  không chặn VS3-4a.
- **TLS body không Content-Length/chunked**: nếu server đóng không gửi `close_notify`, rustls trả
  `UnexpectedEof` thay vì EOF; giữ strict (an toàn hơn, không đoán truncation). Đa số server gửi
  `Content-Length` hoặc `close_notify`; ghi nhận để VS3-4b xử lý.
- Không đụng `pkg.rs`, `frame/**`.
